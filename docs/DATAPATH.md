# K8 Classic Datapath v1

This document freezes the first educational datapath for the discrete-logic K8 Classic.

## Design priorities

1. Understandability
2. Probeability
3. Hand assembly
4. Repairability
5. Availability of standard 74HC/HCT parts
6. PCB cost

Chip count is deliberately not the primary optimisation target.

## Functional blocks

### Data bus

An 8-bit tri-state data bus, DB0-DB7, is the central CPU data path.

Only one bus source may drive the bus during a microstep. Destination registers latch the bus on their explicit load controls.

### Accumulator A

- 8-bit register
- bus input
- ALU input
- bus output
- Z/N flags generated by ALU/result logic

### X and Y registers

- 8-bit each
- independent bus input/output
- used for indexing and general programming

### Program Counter PC

- 16-bit
- incrementer
- high and low byte registers
- address bus source
- explicit load path

### Memory Address Register MAR

- 16-bit
- drives the external address bus
- separate low/high byte registers
- can receive the address-generation result

### Instruction Register IR

- 8-bit
- loaded from the data bus during instruction fetch
- feeds opcode decode/microcode selection

### Stack Pointer SP

- 8-bit
- selects page $01
- increment/decrement control
- bus-visible for teaching/debugging

### Flags F

Architectural flags:

- C Carry
- Z Zero
- N Negative
- V Overflow
- I Interrupt enable
- B Break

Unused/reserved bits remain defined and are not silently repurposed.

### ALU

Use a standard 8-bit 74HC283-style adder chain as the arithmetic core, with logic operations provided by simple 74HC gates/multiplexers.

The ALU is deliberately built from visible 8-bit stages rather than a hidden programmable CPU.

Supported conceptual operations:

- ADD
- SUB
- AND
- OR
- XOR
- NOT
- shifts/rotates

The exact gate-level implementation is frozen during schematic capture, but the external control interface remains ALU_OP + ALU result + carry/overflow generation.

### AGU

The educational 16-bit AGU uses the ALU/adder datapath in two byte phases:

    MAR.low + X/Y -> MAR.low + AGUC
    MAR.high + AGUC -> MAR.high

AGUC is a dedicated one-bit latch.

This deliberately demonstrates why an 8-bit CPU needs multiple phases to perform 16-bit address arithmetic.

### Control unit

The control unit is microcoded.

- IR selects instruction entry
- microstep counter selects timing step
- control ROM produces explicit control signals
- sequencer handles next-step/branch conditions

No opaque FPGA-only control logic is allowed in the Classic implementation.

## Recommended IC families

Prefer 74HC/HCT DIP packages for the hand-built revision where timing permits.

Likely building blocks include:

- 74HC173/574 class registers
- 74HC283 adders
- 74HC157 multiplexers
- 74HC245 bus transceivers
- 74HC138/154 decoders
- 74HC161/163 counters
- 28-pin/32-pin EEPROM for microcode and ROM

Exact part selection remains subject to timing and availability verification.

## PCB partitioning

The first PCB revision should visually separate:

    CONTROL | REGISTERS | ALU | AGU | BUS | MEMORY/I/O

Silkscreen should print signal names at major boundaries. Test points should be provided for:

- DB0-DB7
- AB0-AB15
- clock
- reset
- microstep
- IR/opcode
- ALU carry
- AGUC
- IRQ

## Educational requirement

A learner must be able to single-step:

    FETCH
      -> operand fetch
      -> ALU operation
      -> result writeback

and probe the corresponding buses/signals with a logic analyser.

## FPGA correspondence

The FPGA design will implement these same named blocks and signals, even though synthesis may collapse them internally. The names and signal boundaries remain in the HDL for simulation/debug.
